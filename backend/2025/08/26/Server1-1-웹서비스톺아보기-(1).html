HTML, HTTP, URL과 Netscape

Aug 26, 2025 About 1 min
#Server

웹서비스의 전체적인 틀을 잡아보자 (by 널널한 개발자)

1. HTML, HTTP, URL의 등장

웹의 창시자, 티모시 버너스 리는 논문의 참고자료들을 쉽게 볼 수 있도록 만들기 위해 HTML, HTTP, URL를 만들었고 이에 따라 초기의 브라우저는 “원격지 문서 뷰어”로써만 동작하였다.

HTML은 내용을 담는 text와 속성을 부여하는 tag로 이루어져 있는 하이퍼텍스트다. 초기의 브라우저는 원격지 문서뷰어였다. 더 예전에는 text문서만 다루었지만 tag속성을 부여함으로써, 이를 매핑하는 과정이 필요했고 브라우저는 HTML을 읽어 DOM(Document Object Model)이라는 트리 구조로 매핑했고, 시간이 지나며 이 구조는 나아가 JS와 연계된 virtual DOM 개념까지 발전하게 된다.

브라우저는 URL을 해석해 도메인(example.com), 경로(/index.html) 등을 파싱 TCP 연결을 열고(기본적으로 80포트, HTTPS라면 443포트) HTTP 규약에 맞게 GET 요청 메시지를 생성하여 서버에 보냅니다.

초기의 Server는 HTML저장소일뿐이었다. 예를 들어, 사용자가 HTTP 요청 중 GET 메서드로 특정 URL을 호출하면, 서버는 해당 HTML 파일을 찾아 그대로 응답했고, 브라우저는 이 파일을 받아서 렌더링하여 유저에게 보여주는 역할만 수행했다.

웹서버(송수신), WAS, DB로 구성된 백엔드에서 웹서버의 기능만 한다고 보면 되고 이에 나아가 현재는 HTTP요청을 더 효율적으로 분배해주는 Nginx, apache등이 이에 해당한다.

2. Netscape (꾸밈 및 움직임의 적용)

시간이 지남에 따라 HTML 문서뿐 아니라 디자인(꾸밈)에 대한 요구가 커졌고, 이에 따라 Netscape라는 회사에서 CSS와 JavaScript가 등장했다.

  • CSS: 화면의 레이아웃과 스타일을 담당
  • JavaScript: 사용자 이벤트에 반응하거나 페이지에 동적인 동작을 부여

이 시점에서 UI, 데이터 관리, 제어(Control)를 분리해야 한다는 SW 원칙이 반영되었고, 이를 통해 유지보수가 훨씬 용이해졌다.

즉, 원격지 문서 뷰어에 불과하던 브라우저에 JS 엔진이 추가되면서 “단순 뷰어” → “동적 실행 환경”으로 발전하게 된다. 사용자는 더 이상 단순히 문서만 읽는 게 아니라, 브라우저 안에서 계산·검증·애니메이션 같은 로직까지 경험할 수 있게 된 것이다.

이러한 분리 원칙은 오늘날 서버 개발에서 사용하는 MVC(Model–View–Controller) 구조와도 맥을 같이 한다.

  • View: 브라우저에서 HTML·CSS가 화면을 구성
  • Controller: JS가 사용자 입력을 받아 제어
  • Model: 서버에서 데이터(DB 등)를 가공해 전달

즉, 브라우저에서 시작된 “역할 분리”의 개념이 확장되어 서버 사이드 아키텍처에서도 Model–View–Controller 패턴으로 자리 잡게 된 것이다.

여담이지만 Netscape는 망했지만 이를 계승한 것이 파이어폭스라고 한다.
